First-run tour · design for sign-off · 2026-07-27 (v2)

PeptidePal greets a new user with one tooltip pointing at the Library tab. Same pattern, aimed at what Pepta actually needs a new user to learn. v2 rebuild: the first pass invented its own Home screen and hand-typed pixel coordinates for each highlight, so nothing lined up. This version ports the shipped tokens (radii.card 24, sizes.card.padding 18, PlanCard #EFEBFF borderless, FAB 52×52 r16 in a 58pt slot, tab bar 10/16/14 padding) and — the actual fix — computes every spotlight from its target's measured box at runtime instead of me guessing. Misalignment is now structurally impossible rather than something I eyeball.

Spotlights are measuredEach highlight reads its target's real box. This is exactly what the RN build must do — measureInWindow, not constants — or it breaks on every other device size.
“Paid only” is already freeAccessGate renders MainTabs only when access is active. Non-payers hit the wall and never see tabs — so this needs a first-run flag, no entitlement check.
Home already activatesGettingStartedCard ships today. The tour points AT it rather than repeating it.
Tour = where, card = whatThe checklist teaches what to do; the tour teaches where things live — the FAB and the tabs it never mentions.

Open questions for sign-off

1. Four steps or three? Shorter tours complete more often. Pep is the most cuttable — he greets the user with a bubble ~900ms after Home loads anyway, so step 4 may be telling them what they are about to find out.
2. Progress gets no step, deliberately. On day one it is empty; pointing at a blank chart sells nothing. It earns a mention after the first weigh-in.
3. “Done” should close quietly rather than auto-opening the first task — converting orientation into action is tempting, but it takes control back the moment the user gets it.
4. No replay affordance is designed. If wanted, Settings → Support is the natural home.

Build note carried into implementation: the RN overlay must position each spotlight from measureInWindow on a ref to the real target (and re-measure on rotation / dynamic-type change), exactly as this page measures the DOM. Hardcoded offsets are what produced the v1 misalignment and would ship as misalignment on every screen size that is not the one it was tuned on.
